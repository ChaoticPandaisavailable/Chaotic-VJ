# Realtime VJ Implementation Plan

**Goal:** 按 VJ_Local_Effect_Spec_2026-10-01.md 交付可本地运行、实际可见的音乐驱动混沌视觉与照片队列原型。

**Architecture:** 一个本地 Node 服务承载 Vite/构建产物、认证、图片处理、队列与 WebSocket。独立 visual-engine 与 audio-engine；服务端只授予一个输出端播放租约，实际渲染确认控制照片时钟。控制台预览可让位给外接屏输出，音频采集位于实际输出端，控制面板可关闭。

**Tech Stack:** TypeScript strict、Vite、Three.js/WebGL2、GLSL、Web Audio、Express、Sharp、WebSocket。

## 方案选择

1. 采用规格确定的本地浏览器内核：最快验证 shader，可逐步换桌面音频入口。
2. 桌面外壳能改善设备与窗口集成，但先增加打包成本；本轮不采用。
3. 原生渲染有更直接的硬件控制，但不符合已确定栈；本轮不采用。

## 执行步骤与验收

1. `packages/shared/` 定义参数 schema、照片时间包络和事件。测试 JSON 范围、15/18 秒边界。
2. `packages/visual-engine/` 实现分形流场、局部 signal、背景 ping-pong、独立照片 ping-pong、最终统一色板。实际预览三个连续版本；静音仍演化。
3. `packages/audio-engine/` 实现桌面流、本地文件、频段、flux/onset、累计时钟。测试平滑、静音、低高频差异。
4. `apps/upload-server/` 实现先排序后异步 Sharp、取消标记、持久快照、单播放者、认证、局域网上传。测试 20 张反序处理、处理失败、删除竞态、暂停与重连。
5. `apps/performer/src/` 实现大预览、八宏、色板、音频调制、图队列、纯输出与手机页。浏览器验证操作、console、窄屏。
6. `packages/dj-bridge/` 实现可选 OSC/OS2L 数据适配与超时，不改 VDJ 配置；记录本机版本和真实可用性。
7. `README.md` 与 `docs/` 记录安装运行、参考观察、本机/未验证项目；运行 typecheck、build、test，并保存预览截图与对比入口。

## 视觉决定

演出控制台采用炭黑、暖灰、酸黄绿色状态强调，紧凑仪器刻度与宽幅中央视觉。初始画面是暖白云层在暗部中卷曲，三个版本为稀薄云层、密集折叠、强碎裂。所有画面色来自可编辑色板。照片只在同一流场局部出现，最终包络统一控制纹理/轮廓/颜色/历史。

2026-10-02：已完成本地应用、音频分析、照片 / 管理 / 手机上传、可选 DJ 桥、预设和文档。17 项测试通过，构建通过。用户后续方向优先于最初视觉草案：保留原始复杂混沌，减少硬切片与高频抖动；新增体积风暴和高维场艺术探索；Kick 推动已有亮色大块，带来空间涟漪、惯性和色板变化，不外加笔迹。

后续应以用户最后的修正为准：

- 保留原生混沌的复杂卷曲和层次。用户不喜欢过度简化的形体、硬切片和机械抖动。
- 整体要自然，像观察风暴；体积风暴和受高维结构启发的弦流可继续探索。

- 提升清晰度时优先减少 GPU 重复计算，不能仅凭降分辨率宣称性能改善。
