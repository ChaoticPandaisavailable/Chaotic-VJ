# 丰富、协调、缓慢的动态配色

## 第三轮：明亮主体与明暗区分

第二轮配色需要更亮、更丰富，并兼顾不同色觉条件下的明暗区分。本轮保留连续色域、主辅结构与纯白高光，提高主体而非仅高光的亮度：主色色槽 Oklab L 由约 0.60 提高到 0.705–0.73，色度由约 0.112 提高到 0.15–0.162，超过 sRGB 的部分仍做色域压缩。暗部色槽 L 从 0.335 提高到 0.43；主色在标量 0.43 即显现，降低大片暗棕/暗灰的占比。辅色更鲜明，白色峰值不变，背景仍保留黑色留白。最终实现以本节为准。

参考 [Paul Tol 的色彩方案](https://sronpersonalpages.nl/~pault/) 中鲜明配色与明度区分的方法，没有把定性色板直接混成连续渐变，也不宣称整个 XY 对所有色觉情况都安全。将“晴蓝 · 金黄”作为容易比较的起点；其他 15 个起点与整个色环继续可用。

新增亮度与色度回归测试，以及 Machado、Oliveira、Fernandes (2009) 的 protan/deutan/tritan 三组近似模型检查：在采样 XY 网格上，五个色彩角色的线性相对亮度保持有序，相邻色槽亮度差大于 0.03、对比比值大于 1.25。这些是本项目的层次回归阈值，不是无障碍认证或对用户个人视觉的模拟。矩阵数值及线性 RGB 应用方式与 [Colorspacious 实现](https://github.com/njsmith/colorspacious/blob/master/colorspacious/cvd.py) 核对。构建与全部 53 项测试通过。

仅修改配色色槽、明度分配与一个起点名称/坐标，没有增加全屏渲染步骤。修改前源码和状态位于 `.runtime/before-brighter-colors-2026-10-04/`。

浏览器已加载本轮生产构建，实际检查亮色主体、色板和 360 秒慢变；最终检查时没有浏览器警告或错误。保留用户正在演奏的形态，截图为 `test-results/screenshots/bright-final.png`，16 个配色起点的静态比较为 `test-results/screenshots/palette-proof.png`。本轮未作独立的前后帧率基准比较。

## 第二轮：单帧克制，色域多元

用户指出上一版仍然浑浊，棕黄、荧光青与带色白块互相争夺注意力，并明确允许纯白。根因不只是色度偏高：在空间亮度梯度中沿色相弧线连接冷暖两端，会引入额外的绿、紫、红等颜色。以下保留作过程记录，亮度与色度参数已被第三轮调整。

本轮把主色与点缀分工固定下来：近黑背景、低色度暗部、明确主色、柔和辅色、纯白高光。主色覆盖标量范围的 0–0.64，点缀出现在亮部，0.86–1 逐步归白。这是查找纹理的区间分配，并不保证任何视觉的实际屏幕面积比例。不同形态的亮度分布不变。

X 继续覆盖完整色环，使用 15 个按色系设计的辅色锚点循环连接；Y 从同色到白变为有节制的双色点缀，使用 Oklab 直线混合而非绕行色轮。每帧中间调保持有色，不把整个色域压成灰。提供 16 个演奏起点；主辅色关系按色系分别安排，不再对所有颜色统一增加固定互补角度。高光色槽固定 `#ffffff`，暗部色度下调以减少棕色污染。自动变色继续移动 XY 坐标，保持慢速与连续。

研究与取舍：
- [Paletton](https://paletton.com/)：以主色和关联配色模型组织少量色相，再派生明暗变化；其工具本身使用 RYB，本项目仍使用 Oklab。
- [Pro Color Harmonies](https://github.com/meodai/pro-color-harmonies)：作者区分机械色相旋转与按色系调整的策略，并分配主角、配角及色度关系。本项目独立编写锚点与映射，没有引入依赖或复制其生成代码。
- [Björn Ottosson 的颜色选择器设计](https://bottosson.github.io/posts/colorpicker/)：连续性、独立明度、色域边界等目标存在取舍。二维界面本身不是协调保证，应限制其映射到的参数范围。
- [Adobe 色轮](https://www.adobe.com/uk/creativecloud/design/discover/color-wheel.html)：先确定主色，再选择支持色，并在具体画面测试。
- [Forni 等人的色彩搭配研究](https://arxiv.org/abs/2508.15777)：偏好依赖具体色相，对固定色相间距的通用审美保证应保持谨慎。这里的搭配表是美术选择，不是论文给出的最优调色板。

验证：构建、51 项测试通过。新增全域空间梯度检查：主色段不偏离其色相、亮部不产生高色度杂色、端点为纯白；3600 个色相步长检查锚点与接缝连续。浏览器复测用户举例位置 X=0.12 / Y=0.85，并检查蓝金、翡翠杏白和窄屏面板；无 shader 报错。截图保存为 `restrained-amber.png`、`restrained-cobalt.png`、`restrained-jade.png`、`restrained-control.png`。不增加全屏通道。修改前源码与状态位于 `.runtime/before-restrained-colors-2026-10-04/`。

## 初版记录

旧 XY 仅在少数琥珀、青瓷、灰蓝色板间混合，低浓度区域大量使用低色度灰色。用户希望整块区域都可用、拥有多种颜色关系和缓慢演化，同时保留留白、画质及演出控制。

采用完整色环和固定明度角色：深背景、暗部主色、中间主色、浅色辅色、带色高光。X 遍历全色相，Y 将邻近色缓慢展开为较强的双色关系；低 Y 仍保持有色中间调。提供 12 个双色起点。沿色相弧线插值并在越界时压缩色度，避免互补色在过渡中混成灰色，避免单通道硬裁剪造成偏色。

慢变以 90/180/360 秒为周期，可关闭。限定 XY 区间时只在区间内往返；手动选色时平滑衔接。通过输出端遥测同步颜色相位，Freeze / Blackout 停止自动变色。HEX 色板独立保存，使用 XY 不覆盖它。MIDI target 名称及范围数据不变，标签更新为色相、配色。

仅 256×1 GPU 色板纹理增加极坐标插值与色域压缩，不增加全屏后处理通道。验证全色域色度/明度边界、色环连续性、慢变帧率独立性、暂停、区间、窗口同步、旧配置与自定义配色兼容；实际输出检查双色、灰阶、冻结和性能。

参考：
- [Adobe 色轮与配色关系](https://www.adobe.com/uk/creativecloud/design/discover/color-wheel.html)：邻近色、互补色、三角色与主辅关系。这里的美术比例是项目的设计选择，不是普遍保证美观的公式。
- [Björn Ottosson：Oklab](https://bottosson.github.io/posts/oklab/)：分离感知明度、色度和色相。
- [W3C CSS Color 4 色相插值](https://www.w3.org/TR/css-color-4/#hue-interpolation)：色相弧线、无色端点处理与色域映射的依据。实现独立编写。

Impeccable 的本地 context 启动器缺少引擎，本轮依据已读取的 colorize / craft-floor 指南和实际项目源码继续，不安装额外工具。

## 验证结果

- TypeScript 与生产构建通过，49 项测试通过。色域测试覆盖 73×21 个 XY 位置的有色中间调、辅色色度、明度顺序与左右接缝；慢变测试覆盖不同帧率、冻结、区间边界与旧配置默认值。
- 应用内实际检查蓝金、青紫和琥珀青碧关系，自动变色中的色槽和 XY 白点连续移动。切回自定义 HEX 后，原有五个色值完整恢复，自动变色关闭。两个窗口未捕获 WebGL 或 shader 错误。
- 自动变色开启时冻结，间隔截取两张输出图；画面内部 1200×620 区域平均与最大 RGB 差均为 0。
- 本轮实际上下文为 RTX 4070 Laptop GPU。原生混沌输出 1920×1080，内部场 1920×1080，短时读数约 240 FPS、GPU 0.3–0.4 ms；控制台预览为 30 FPS / 720×405。这不是前后性能对比，也不代表其他风格、4K 或长时演出表现。
- 检查桌面与窄屏面板；临时尺寸覆盖已复位。保留紧凑 XY、两轴滑块与单行慢变控制。
