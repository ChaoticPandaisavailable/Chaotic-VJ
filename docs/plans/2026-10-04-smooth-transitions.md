# 按需平滑切换 · 2026-10-04

用户接受点击后的准备延迟，希望当前画面先继续播放，目标就绪后再过渡；不需要后台预渲染所有风格。此次保留原生混沌、体积风暴的已恢复形态和参数，也不改配色。

## 实现

- 点击触发目标着色器异步编译；粒子与几何在独立准备步骤上传资源。过渡公共材质在首次请求时准备，之后复用。没有启动时遍历全部风格的预热。
- 等待时保持旧场景的形态参数和动画，目标准备完成后才计时。后续请求取代过时目标；已提交给驱动的编译无法取消，但不会把过时目标显示出来。
- 切换瞬间从最近两帧估计最大 256×144 的 GPU 运动场，过渡期间用它推动旧画面，并结合轮廓形变。过渡后端点保持原始画面。中途再次选择使用实际显示的混合画面；窗口比例变化也保留运动场，避免纹理清空产生位移跳变。
- 单场景模式不同时持续运行两套完整生成器；开源源准备期间短暂保留旧源与目标源，之后退休旧源。A/B 演奏仍按其功能运行两个选中的视觉。用过的普通着色器和几何会缓存，但不继续逐帧渲染未选中的风格。
- MilkDrop 的慢速变化在每帧方程中连续演化，避免每次随机构图 revision 都重新加载预设、编译着色器。修改漫游强度本身仍会加载更新后的方程。
- A/B 混合输入增加轻度平滑；场景过渡使用配置中的完整持续时间。准备提示为“正在准备平滑切换…”。

## 验证

`npm run build`（包含 TypeScript 检查）通过，`npm test` 55 项通过。新增检查涵盖运动场输入、快速中断时的纹理取样、过渡中改变尺寸；已有测试覆盖冻结、不同刷新率、MIDI、照片队列与色彩连续性。

开发检查页 `apps/performer/transition-check.html` 不包含在正式构建入口中。运行 Vite 后打开 `/transition-check.html`，点击“开始检查”。固定 1280×720、内部场比例 100%，不运行动态降分辨率，按 3.6 秒切换多个风格，再以 180 毫秒连续打断并回到原生混沌。结果包括请求风格、实际风格、准备状态、帧间隔及 CPU 提交耗时。

本机 RTX 4070 Laptop GPU 的检查结果保存于 `test-results/transition-after-demand.json`。15 个阶段均完成，最终实际风格正确、准备与过渡结束，无 shader 错误。首次创建引擎有一次约 58 毫秒帧间隔；之后切换阶段没有超过 33.4 毫秒的帧间隔，最长约 29 毫秒。180 毫秒连续选择期间过渡持续进行，最后稳定到原生混沌。

这些是一次短时本机检查，不代表 HDMI 全分辨率、同时音频/VDJ 或所有场景的稳定帧率。前后检查的浏览器调度、驱动缓存和其他窗口负载不同，不能据此计算性能提升百分比。旧 `transition-before.json` 的 MilkDrop 阶段受开发服务器对包含百分号的依赖文件路径处理影响，不能用作开源效果的有效基线；开源效果在正式构建中另行实看光速隧道、液态银幕切换。

## 使用

服务无需改配置。重新构建后需刷新控制台和已经打开的独立输出页，现存页面不会自动替换生产脚本。首次切换复杂效果仍可能出现短时编译/上传成本；准备延迟允许先保留旧画面，不保证驱动工作完全没有帧耗时。
